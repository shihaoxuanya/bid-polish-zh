# 信息化标书去ai味

给编写信息化技术标的投标团队用。把已有的实施、迁移、运维等章节交给 Codex，它会删去重复表态，把绕口的句子改成能直接核对的工作安排。改稿时逐项核对谁负责、什么条件下开始、多久要完成哪件事，并保留对应的评分原词。比如原稿写“力争恢复”，改稿就要保留“力争”这层承诺力度。

可以**直接贴一段文字**看改稿，也可以**提交 Word 技术标**，收到保留原有格式的修订副本，在 Word 里逐条接受或拒绝。附上招标文件或评分表后，如两份材料的承诺有出入，疑点会标在原句旁，便于投标负责人决定。

## 修改前后示例

以技术标第 3.2 节的“一级故障响应”为例。这个项目的评分表把服务动作称为“电话响应”。

**原稿**（删除线标出可省去的开场和收尾）

> ~~为进一步提升故障响应工作的规范化水平~~，试运行期间，值班工程师在接到一级故障通知后，应在 30 分钟内以电话方式向采购人作出响应，并将本次电话响应的时间填写至故障工单中。~~通过上述措施，实现故障响应过程的有效留痕~~。

**修订后**

> 试运行期间，值班工程师接到一级故障通知后，应在 **30 分钟内向采购人作出电话响应**，并在故障工单中记录电话响应时间。

删去开场和收尾后，评委仍能用评分表里的“电话响应”找到这项承诺。30 分钟从工程师接到一级故障通知时算起，实际响应时间可查故障工单。

**如果招标条款与原稿冲突**，正文保留原承诺，投标负责人会在原句旁看到这样的 Word 批注。

> 技术标第 3.2 节约定“30 分钟内”，采购需求第 4 项要求“15 分钟内”。两处均指接到一级故障通知后的电话响应，请投标负责人确认时限。

## 安装到 Codex

把下面这句话发给 Codex 即可。

```text
$skill-installer 请从 https://github.com/shihaoxuanya/bid-polish-zh 安装仓库根目录的技能，名称为 bid-polish-zh。
```

也可以从 Gitee 下载压缩包。解压后，把包含 `SKILL.md` 的那层目录命名为 `bid-polish-zh`，放入个人目录 `~/.agents/skills/`。安装后应能找到 `~/.agents/skills/bid-polish-zh/SKILL.md`。[Gitee 仓库](https://gitee.com/rhoxy/bid-polish-zh) · [Codex 技能目录说明](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)

## 使用方法

### 处理 Word 技术标

在 Codex 中附上投标原稿 `.docx`。如果需要核对某项承诺，同时附上招标文件并说明哪份是原稿。

> 用 $bid-polish-zh 轻改《技术标.docx》的实施和运维两章，保留原格式。参照随附的采购需求核对响应时限，有冲突就在原句旁加批注。

原稿保留，修订副本默认命名为 `技术标_语言修订版.docx`。在 Word 的“审阅”选项卡逐条查看即可。修订沿用原位置的文字格式，保留段落、编号、表格、图片及页眉页脚。文字缩短后可能自然换行、换页。遇到一句话跨越加粗型号和交叉引用、无法安全修改时，会留下建议。

### 先试一段文字

把下面这句连同你要改的段落一起发给 Codex 即可。

> 用 $bid-polish-zh 轻改下面这段运维响应。保留责任人、时限和起算点，直接给我改稿。

## 适用范围和运行条件

- 适合已有的需求理解、实施、迁移、灾备、运维和培训章节。采购方引文、固定承诺函、报价、签章页和偏离表默认保留原文。
- 直接贴文字即可试用。处理 `.docx` 的脚本使用 Python 和 `lxml`。仓库附带的 Word 版面复核脚本需要 Windows 和桌面版 Microsoft Word，可在临时副本中接受或拒绝修订、刷新目录并导出 PDF。
